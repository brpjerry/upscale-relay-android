The app no longer makes you wait for things you did not ask for.

**Loading screens only appear for something you started.** Starting a video,
opening a folder, paging or re-sorting the library, and pressing Connect or
Reconnect still show that they are working. Everything the app does on its
own now happens behind a library that stays on screen and usable:

- **Leaving a video** puts you straight back in the folder you came from, at
  the same scroll position and with the same episode still selected. The
  "Connecting…" and "Loading…" screens that used to sit between the player
  and the list are gone; the fresh connection is made behind it.
- **Waking the tablet or returning to the app** no longer raises a
  "Reconnecting to the server" card over the list. If the connection died
  while the tablet slept it is re-made silently, and if it survived, the
  open folder is quietly refreshed so new files show up without a manual
  reconnect.
- **Opening the app** shows the folder you last had open immediately, from a copy saved on the tablet, and connects
  behind it. The list is swapped for the server's current one when it
  arrives.

If you tap something that needs the server while one of those background
connects is still running, that action waits for it — so the wait shows up
only where you are already expecting one.

**A connection error means the server really cannot be reached.** Losing the
connection is the app's problem to fix, not something to announce:

- **Reconnecting is no longer a countdown.** The "attempt 2 of 6" card, the
  retry timers behind it and the **Stop trying** button are gone, in the
  player and in the library. A connection is re-made once, when there is a
  reason to: you asked for something, the app came back to the foreground, or
  the network returned.
- **In the library nothing is shown at all** when the connection drops. It is
  re-made quietly; if that does not work, the next thing you tap connects
  again, and only then — if the server still cannot be reached — do you get a
  message. A later successful connect takes that message down by itself.
- **In the player** a dropped stream reconnects under the ordinary loading
  screen and resumes where it stopped. If that fails you get one error with
  **Retry**, which now resumes the video at the same position rather than
  returning to the library; the network coming back retries by itself.
- **Waking the tablet** no longer races the Wi-Fi: a connect made while the
  radio is still down waits for the network instead of failing into it.
- Opening a folder or starting a video on a connection that died unnoticed
  reconnects and tries again by itself instead of failing.
- The "Reconnect automatically during playback" setting is removed;
  reconnecting is simply what the app does.

**Settings**

- **"Connect automatically" is removed**; the app always connects to the
  saved server when it opens. If the server is not there it says nothing and
  leaves the connect panel (or your cached folder) on screen — pressing
  Connect is what reports a problem.
- **The model has a page of its own.** Settings shows the current default
  model with a **Change** link; the full list, with each model's scale
  factor, opens on a separate page scrolled to your selection, instead of
  twenty-odd radio buttons pushing every other setting off the screen.
- Backups written by earlier versions still import; the two removed settings
  in them are ignored.

**Fixes found along the way**

- The Recent tab can open a video without visiting the Server tab first; it
  connects on demand, and shows the reason on the Recent tab if it cannot.
- Stopping a video no longer lets the dying session's "connection reset"
  start a reconnect attempt or flash an error over the library.
- A folder request that was still in flight when the connection was replaced
  could leave the library greyed out; the request now always cleans up after
  itself.
- A background reconnect attempt that failed could clear an unrelated error
  message that was still on screen.

Checked on a Galaxy Tab S9 Ultra against a live relay: cold start onto the
cached folder, opening folders, play and exit on `passthrough`, starting a
video again immediately after leaving one, and home/resume. Outages were
simulated by cutting a forwarder between the tablet and the relay: with the
library open nothing is shown, coming back to the app reconnects silently, a
folder tapped while the relay is away reports that it cannot be reached, and
the same tap once it is back opens the folder and clears the message. The
player's reconnect could not be exercised that way and is untested on the
device.

This release is signed with the same key as v0.15.0 onwards and upgrades over
them normally.
